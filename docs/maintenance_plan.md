# План сопровождения программной системы

## Цель сопровождения ПС

Цель сопровождения программной системы прогнозирования соотношения браков по регионам Российской Федерации - обеспечить стабильную работу проекта, исправление ошибок, адаптацию к новым требованиям и постепенное улучшение качества кода.

## Корректирующее сопровождение

Корректирующее сопровождение связано с исправлением найденных ошибок. Например, если приложение неправильно обрабатывает CSV-файл или модель возвращает некорректный прогноз, создается задача в GitHub Issues, после чего ошибка исправляется в отдельной ветке.

## Адаптивное сопровождение

Адаптивное сопровождение требуется при изменении внешних условий: обновлении версии Python, библиотек pandas, scikit-learn и Streamlit, изменении структуры входных данных или переходе к использованию PostgreSQL как проектируемой базы данных.

## Совершенствующее сопровождение

Совершенствующее сопровождение направлено на развитие системы. Возможные улучшения: добавление новых факторов, расширение отчета, визуализация кластеров, сравнение нескольких моделей прогнозирования и добавление фильтров по регионам и годам.

## Превентивное сопровождение

Превентивное сопровождение помогает снизить риск будущих ошибок. Для этого используются тесты pytest, понятная структура модулей, обновление документации, проверка зависимостей и регулярный просмотр кода перед слиянием изменений.

## Работа через GitHub Issues

GitHub Issues используются для фиксации ошибок, предложений и учебных задач. В задаче указываются описание проблемы, ожидаемый результат, фактический результат и критерии готовности.

## Работа через Pull Request

Изменения выполняются в отдельной ветке и отправляются через Pull Request. В Pull Request описываются цель изменений, список измененных файлов и результаты проверки. Перед слиянием желательно выполнить тесты.

## Стратегия ветвления GitFlow

- `main` или `master` - стабильная ветка проекта.
- `develop` - ветка для объединения готовых учебных изменений перед релизом.
- `feature/*` - ветки для новых функций.
- `hotfix/*` - срочные исправления ошибок в стабильной версии.
- `release/*` - подготовка релизной версии.
- `maintenance/*` - изменения, связанные с сопровождением, документацией и техническим обслуживанием.

## Контроль качества через pytest

Для контроля качества используется pytest. Минимальный набор тестов должен проверять подготовку признаков, обучение модели, получение прогноза и совпадение длины прогноза с количеством исходных строк.

## Возможная интеграция GitHub Actions

GitHub Actions может автоматически запускать тесты при каждом Pull Request. Это позволит раньше находить ошибки и контролировать работоспособность проекта после изменений.

## Обновление README и CHANGELOG

README обновляется при изменении структуры проекта, способов установки, запуска приложения и тестов. CHANGELOG можно использовать для фиксации важных изменений по версиям лабораторных работ.

## Жизненный цикл изменения

Обнаружение проблемы -> Issue -> ветка -> исправление -> тесты -> Pull Request -> слияние -> релиз.
